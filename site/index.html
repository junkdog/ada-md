ada

A fast terminal markdown viewer, for one file or a whole vault of notes.

Follow links and come back to where you were, see what git says changed, read wide tables at any width, and look at the pictures.

cargo install --git https://github.com/junkdog/ada-md
ada index.md

Tables you can work with

Sorting knows its units: 350 µs, 12 ms, 1.2 s, 1m 30s and 6 days sort as the durations they are, 1,440 as a number and €420 as money. In a long table, the header row stays on screen as it scrolls.

s sort by a column ← → another table t auto, grid, records

At any width

Prose rewraps and tables re-lay out the moment the terminal changes size. A table too wide to fit turns into records, a card per row; widen the terminal and the grid comes back.

Links you can walk

Relative paths, [[wiki links]], anchors and src/main.rs#L42. Back and forward return to the same spot, with the same link focused. The outline and the list of links filter as you type, and take you there.

Tab focus Enter follow BS back L forward o outline l links

A git gutter

The gutter marks what git says changed in the rendered note: added and modified lines, staged and unstaged, each in its own color.

]c [c next, previous change

Search that sees through markup

A regex matches the text as you read it, across bold, italic and plain, as you type. Link targets match too, and it's smart-case.

/ search n N next, previous

Inline images

png and jpeg, right in the note, over kitty, sixel or iTerm2, with half-blocks as the fallback, and sixel inside tmux when it can. A link to an image opens it full screen.

Also

  • Not only markdown

    Code, config and other text files open whole and highlighted, in some 200 languages; main.rs#L24 lands on line 24. w wraps code or scrolls it sideways.

  • Callouts, footnotes, task lists

    GitHub's five callout kinds, footnotes you can follow, and checkboxes.

  • Live reload

    Reads the file again the moment it changes, keeping its place. e opens $EDITOR at the line on screen.

  • Pipes and previews

    --print writes to a pipe at any width: fzf --preview 'ada --print {}'.

  • Your keys

    Remap any action, including two-key sequences like "g g", in config.toml.

  • Record and replay

    --record a session and --replay it to the same frames: a bug report that reproduces.

Where ada isn't first: glow writes about a third fewer bytes per page, and md-tui uses less memory on the smallest note. Each viewer ran pinned to four physical cores of the same machine, in a 120×40 pty; the numbers are medians of 3–5 runs. The harness is in bench/b2.

No crashes, on any input

ada is fuzzed as whole sessions, not one function at a time: a document, then up to 64 things a reader, the file system, git or the terminal can do, in any order.

  • Any document

    Markdown, code, config, plain text and images, built from random bytes and a dictionary of the parts markdown parsers find hardest.

  • Any input

    Every action, through the real keymap or directly: scrolling, links, search, sorting, the outline, themes, and resizes at any size.

  • A world that answers badly

    Links to missing or corrupt files, fuzzed git hunks, images that report zero or huge sizes, and results that arrive late, out of order, or after their document is gone.

  • Every frame checked

    Each step paints through ada's real diff and encoder into a vt100 terminal emulator, which must show exactly what ada meant to draw, cell by cell: glyphs, colors and attributes.

Every interaction is a message, so a recorded session replays to identical frames: --record makes a bug report that reproduces. A deterministic stand-in for the fuzzer runs with every cargo test.

Install

cargo install --git https://github.com/junkdog/ada-md

Rust 1.99 or newer, and a C compiler: highlighting runs on Oniguruma, built from source. For a pure-Rust build, add --no-default-features. Git integration runs the git command.

# read a note
ada notes/today.md

# from a pipe
git show HEAD~3:README.md | ada

# code, config and images too
ada src/main.rs
ada plot.png

# as an fzf preview
fzf --preview 'ada --print {}'

Press ? in ada for the keys. The README has every key and option.
